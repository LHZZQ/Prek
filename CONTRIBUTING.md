# Contributing to Prek

Welcome!

Thanks for your interest in contributing to Prek

This document outlines how our team collaborates and how to make changes smoothly and consistently.

---

## How We Collaborate

Prek is developed by a small internal team. To keep work organised and avoid conflicts, all changes follow the same workflow.

---

## Setting Up Locally

1. Clone the repository from GitHub.
2. Open the project in your preferred editor.
3. Make sure the app runs locally before starting any work.

---

## Planning Your Work

- Decide what feature, improvement, or fix you want to work on.
- Create an issue describing the task.
- Include a short explanation of the goal and expected outcome using the template already automatically available.
- Create a new branch from the issue using GitHub’s branch-from-issue feature.

---

## Working on the Code

Pull the latest changes before you begin:

- git pull

Switch to different branches:

- git switch (BRANCH NAME)

To add locally, commit, and push your changes:

- git add (YOUR FILE PATH)
- git commit -m "(YOUR MESSEGE)"
- git push origin (BRANCH NAME)

---

## Before You Open a PR

To help reviews go smoothly, please check the following before submitting:
- Your work is on a separate branch with a clear, descriptive name
- The Pull Request focuses on a single feature or fix
- All changes have been tested locally
- Related issues are referenced or closed where applicable
- The Pull Request description is fully completed and reviewers are assigned
- All PRs must pass formatting and static analysis checks.
